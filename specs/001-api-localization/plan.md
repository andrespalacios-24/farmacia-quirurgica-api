# Implementation Plan: API Localization (i18n) Support

**Branch**: `[001-api-localization]` | **Date**: 2026-08-29 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-api-localization/spec.md` + User instruction: "use a recommended library for translations in fastapi or do whats best"

## Summary

Add robust, highly performant localization to all domain exceptions and API responses, allowing seamless switching between English and Spanish via the `Accept-Language` HTTP header, with Spanish as the fallback.

## Technical Context

**Language/Version**: Python 3.12+
**Primary Dependencies**: FastAPI, Pydantic V2, pytest (NEEDS CLARIFICATION: Should we use `fastapi-babel` or implement a custom lightweight JSON loader as discussed in Clarification?)
**Storage**: In-memory dictionary loaded from JSON files.
**Testing**: pytest with `httpx.AsyncClient`
**Target Platform**: WSL2 / Ubuntu (Linux server)
**Project Type**: web-service (Microservice)
**Performance Goals**: 0 ms perceivable latency overhead for translation extraction.
**Constraints**: Fully async (no blocking I/O during request lifecycle).
**Scale/Scope**: ~100-500 translation keys initially, supporting `en` and `es`.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Asynchronous by Default**: PASS (Translations will be loaded into memory at startup, avoiding blocking file I/O during requests).
- **Strict Layering**: PASS (Translation lookup will happen in the Exception Handler or via Dependency Injection, keeping Routers clean).
- **Type Safety**: PASS (Translations can be typed or wrapped in a service class).
- **Centralized Exception Handling**: PASS (This feature directly integrates with the global exception handler).
